# Kirishot J0 + J1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mesurer la latence de l'approche A (spike J0), puis livrer le jalon J1 : Impr. écran → écran figé → sélection d'une zone, d'une fenêtre ou de l'écran → image enregistrée et copiée selon les réglages.

**Architecture:** Une application Tauri 2 qui vit dans la zone de notification. Rust capture tous les écrans (`xcap`), garde les pixels en mémoire et les sert en RGBA brut par le protocole `kirishot`. Une fenêtre de sélection React par écran, créée cachée au démarrage, renvoie seulement une cible (rectangle, fenêtre ou écran). Rust découpe, encode, enregistre et copie. Les commandes sont typées par tauri-specta, et chaque type de fenêtre n'a accès qu'à ses commandes.

**Tech Stack:** Tauri 2.12, Rust stable (msvc), `xcap` 0.9.8, `image` 0.25, `windows` 0.62, `clipboard-win` 5.4, tauri-specta `=2.0.0-rc.26`, React 19, TypeScript ~5.9, Vite, Tailwind 4, shadcn/ui, Vitest 5, ESLint 10 et Prettier 3, pnpm 10.

**Spec:** [`docs/superpowers/specs/2026-11-01-kirishot-design.md`](../specs/2026-11-01-kirishot-design.md). Les sections citées (§ 3.2, § 7.3…) renvoient à cette spec. L'exécutant lit les deux documents.

- Le dossier de destination par défaut est le dossier Images connu de Windows, suivi de `Kirishot`. Il n'est jamais écrit en dur.
- Formats : PNG par défaut, JPG en qualité 90, WebP sans perte.
- Une copie écrit toujours deux formats : le format enregistré `PNG` et `CF_DIBV5`.
- Raccourcis par défaut en J1 : `PrintScreen` (zone) et `Shift+PrintScreen` (écran entier sous la souris).
- Règles de la sélection (§ 3.2) :
  - une sélection plus petite que 4×4 px compte comme un clic ;

- Couleurs : jetons du § 2. L'accent est `#FF5B38`. La fenêtre de sélection est toujours sombre, et le fond de toutes les fenêtres est `#0E1014` pour éviter un flash blanc.
- Branches : tout J1 se fait sur `feat/j1-capture`, créée depuis `main`. Le spike se fait sur `spike/latence`, qui n'est jamais fusionnée.

## Review Focus

Ce sont les cinq situations que la spec implique et qui risquent le plus de mal tourner pour un utilisateur. Chacune a un test dans la tâche qui possède le code concerné.

1. **Deux appuis rapides sur Impr. écran**, ou un appui pendant une sélection : il ne doit y avoir qu'une seule session, et le second appui est ignoré. Test `second_begin_is_refused_while_active` (tâche 10).
2. **Un écran secondaire à gauche ou au-dessus du principal** (origine négative, par exemple x = −1920) : la découpe et les contours des fenêtres doivent rester justes. Tests `windows_for_monitor_handles_negative_origin` et `monitor_at_point_handles_negative_origin` (tâche 5).
3. **Une sélection tirée de droite à gauche, au-delà du bord de l'écran, ou minuscule** : le rectangle est normalisé et borné à l'écran, et un clic hors d'une fenêtre ne capture rien. Tests de la tâche 9 et `region_is_clamped_to_monitor` (tâche 5).
4. **Un dossier de destination disparu, un nom de fichier vide ou réservé, ou un fichier qui existe déjà** : Kirishot se replie sur `Images\Kirishot`, produit un nom valide et ajoute « (2) ». Tests des tâches 7 et 8.
5. **Un écran branché, débranché, ou une échelle changée entre deux captures** : les fenêtres de sélection sont recréées à la bonne taille. Test `needs_recreate_when_scale_changes` (tâche 10).

  - Le protocole `kirishot` répond à `/frame/<écran>` avec 8 octets d'en-tête (largeur, puis hauteur, en u32 little-endian) suivis des pixels RGBA. Il ajoute l'en-tête `Access-Control-Allow-Origin: *`.
  - Une fenêtre `overlay-<i>` par écran (`overlay.html`) est créée au démarrage, sans bordure, toujours au premier plan, absente de la barre des tâches, avec `background_color(Color(14, 16, 20, 255))`.
  - La variable d'environnement `KIRISHOT_SPIKE_VARIANT` choisit la variante :
    - `v1` : la fenêtre est créée cachée, à la position et à la taille physiques de son écran, puis affichée avec `show()` ;
    - `v2` : la fenêtre est créée visible en `(-32000, -32000)`, puis déplacée sur son écran avec `set_position`, puis `set_size`.
  - Rust émet l'événement `spike-capture`.
  - La commande `spike_ready(fetch_ms, draw_ms)` affiche la fenêtre (selon la variante) et note `show_ms`.
  - La commande `spike_painted()` note `total_ms = t0.elapsed()`, ajoute une ligne `run,variant,backend,monitors,capture_ms,fetch_ms,draw_ms,show_ms,total_ms` à `%TEMP%\kirishot-spike.csv`, puis recache la fenêtre au bout de 400 ms.
- **Front (`spike.ts`)** : à la réception de `spike-capture`, la page fait un `fetch` de `http://kirishot.localhost/frame/<i>`, construit une `ImageData`, appelle `putImageData` sur un canvas plein écran, puis appelle `spike_ready`. Au premier `visibilitychange` visible, elle attend deux `requestAnimationFrame`, puis appelle `spike_painted`.
- **`scripts/spike/press.ps1 -Key PrintScreen|CtrlAltK -Count 20 -IntervalMs 1500`** : envoie la touche avec `user32!keybd_event` (via `Add-Type`), autant de fois que demandé.

`repair` suit l'algorithme ci-dessous. Il n'y a pas de code par champ : c'est la désérialisation qui valide chaque feuille.
```rust
pub fn repair(file: Value) -> (Settings, Vec<String>) {
    let defaults = serde_json::to_value(Settings::default()).unwrap();
    let mut merged = defaults.clone();
    let mut warnings = Vec::new();
    for (path, value) in leaves(&file) {                 // feuille = valeur non objet ; path = ["save", "format"]
        if pointer(&defaults, &path).is_none() { warnings.push(format!("unknown key {}", path.join("."))); continue; }
        let mut candidate = merged.clone();
        set_pointer(&mut candidate, &path, value);
        if serde_json::from_value::<Settings>(candidate.clone()).is_ok() { merged = candidate; }
        else { warnings.push(format!("invalid value for {}", path.join("."))); }
    }
    let (settings, more) = validate(serde_json::from_value(merged).expect("defaults with valid leaves"));
    warnings.extend(more);
    (settings, warnings)
}
```

`load` suit ces étapes :
- **Fichier absent** : charger les valeurs par défaut et les enregistrer.
- **Erreur de lecture** : charger les valeurs par défaut, avec un avertissement.
- **JSON illisible** : renommer le fichier en `settings.bak.json` (en écrasant l'ancien), charger les valeurs par défaut, les enregistrer, et mettre `reset_from_corrupt` à `true`.
- **Sinon** : appeler `repair`, puis enregistrer le fichier si des avertissements existent.

`save` écrit `settings.json.tmp`, puis le renomme avec `std::fs::rename`.

L'en-tête `BITMAPV5HEADER` fait 124 octets, tous en little-endian. Les champs non listés valent 0.

| Offset | Champ | Valeur |
|---|---|---|
| 0 | bV5Size | 124 |
| 4 | bV5Width | largeur |
| 8 | bV5Height | hauteur (positive : lignes de bas en haut) |
| 12 | bV5Planes (u16) | 1 |
| 14 | bV5BitCount (u16) | 32 |
| 16 | bV5Compression | 3 (`BI_BITFIELDS`) |
| 20 | bV5SizeImage | largeur × hauteur × 4 |
| 40 / 44 / 48 / 52 | masques R / G / B / A | `0x00FF0000` / `0x0000FF00` / `0x000000FF` / `0xFF000000` |
| 56 | bV5CSType | `0x73524742` (`LCS_sRGB`) |
| 108 | bV5Intent | 4 (`LCS_GM_IMAGES`) |

Les pixels suivent l'en-tête en BGRA, de la ligne du bas à celle du haut.
