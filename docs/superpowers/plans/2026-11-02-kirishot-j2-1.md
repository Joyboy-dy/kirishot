# Kirishot J2.1 « Corrections après tests » Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix what the J2 tests found before `feat/j2` merges: distinct Zone/Window modes, a « ? » shortcut sheet instead of the hint bar, a working text tool, editor options that all work and only show when they apply, a bubble that stays on screen, a responsive editor, and clean copy/save feedback.

**Architecture:** Pure TypeScript functions carry every decision a test can pin (selection state machine, option table, bubble placement, toolbar layout, dash patterns, arrow geometry, feedback timing); React components only render their results. Two settings join `capture` in Rust and travel to the overlay in `OverlaySession`. Export draws a clone of the content layer on an offscreen Konva stage, so the visible stage never moves.

**Tech Stack:** unchanged from J2 (Tauri 2.12, Rust 2024, React 19, TypeScript, Tailwind 4, react-konva, `radix-ui`). The style and palette menus use `Popover` from the existing `radix-ui` package; no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-02-kirishot-j2-1-corrections-design.md` (binding), on top of `docs/superpowers/specs/2026-11-02-kirishot-usage-quotidien-design.md`.

## Global Constraints

- Branch `feat/j2`; nothing merged or pushed without the user's go-ahead.
- No simulated keyboard or mouse input on the user's PC: anything visual goes to the manual checklist (Task 9).
- UI strings in French through `src/i18n/fr.json`; code and comments in English, matching the existing code.
- Settings stay `version: 1`; new fields get defaults through the existing leaf-by-leaf merge in `settings/store.rs`: `capture.mode: "region"`, `capture.toolbarPosition: "top"`.
- Document fields read with defaults from existing autosaved documents: `highlighter.opacity` 1, `pixelate.block` 16.
- Values pinned by the spec: opacity slider 10–100 %; dashes `[3w, 2w]`, dots `[0, 2w]` with round caps; pixelate blocks 8 / 16 / 28 px; bubble margin 8 px; layout breakpoints 1 100 and 760 px; editor minimum 520 × 400; check mark 1.5 s, check before close 400 ms, status message 4 s, spinner after 300 ms; window title label truncated at 60 characters.
- `src/lib/bindings.ts` is regenerated by `cargo test` and committed; Python file writes use `newline=''`.
- `pnpm lint`, `pnpm typecheck`, `pnpm test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` green after every task.

## Review Focus

1. **Text typed right after the click.** With the text tool, click then type immediately (no pause): every character lands in the field, and nothing is dropped when the click lands on an existing annotation or on the image edge. Test: Task 5 `textPointer` cases.
2. **Old documents and settings.** An autosaved document from J2 (no `opacity` on highlighters, no `block` on pixelate areas) and a J2 `settings.json` (no `mode`, no `toolbarPosition`) load without loss. Tests: Task 3 `normalizeDoc`, Task 1 old-file test.
3. **Bubble in a tiny window or on a huge selection.** At 520 px wide, or with a selection larger than the view, the bubble stays fully visible and usable. Test: Task 6 `bubblePlacement` edge cases.
4. **Mixed selection.** Selecting an arrow and a highlighter shows only colour, size and opacity; changing one is one undo step for both. Test: Task 3 `optionsFor` intersection, Task 6 `applyStyle`.
5. **Export of a large, zoomed, cropped capture.** Export at 1:1 still matches the crop exactly after the offscreen change, and the visible view does not move. Test: Task 8 keeps the J2 `exportRect` tests; the visual part is manual item.
