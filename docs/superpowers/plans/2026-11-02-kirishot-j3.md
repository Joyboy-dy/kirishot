# Kirishot J3 « Une application aboutie » Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Kirishot a complete daily application: it opens when launched, keeps a searchable history, edits without covering the image or duplicating files, lets the user rename files, pick any colour and set every shortcut and preference it shows.

**Architecture:** A new Rust `history` module owns `%APPDATA%\Kirishot\history\` (one folder per capture plus an atomic `index.json`) and emits `history-changed`; capture delivery, thumbnails and editor export report to it. The editor tracks a `savedDoc` and the current file path to derive `never | clean | dirty`, and Rust export gains replace / new-version / rename. The main window becomes a sidebar app (Historique, Raccourcis, Réglages, À propos) whose pages are thin React views over pure, tested functions.

**Tech Stack:** unchanged (Tauri 2.12, Rust 2024, React 19, TypeScript, Tailwind 4, react-konva, `radix-ui`); new: `tauri-plugin-autostart` 2 (Rust crate only, driven from Rust), `react-colorful` 5 (MIT), `windows` features for the cursor (`Win32_UI_WindowsAndMessaging` already present, plus `Win32_Graphics_Gdi`).

**Spec:** `docs/superpowers/specs/2026-11-02-kirishot-j3-application-design.md` (binding), on top of the J2.1, J2 and v1 specs (`docs/superpowers/specs/`).

## Global Constraints

- Branch `feat/j2`; nothing merged or pushed without the user's go-ahead. No simulated keyboard or mouse input on the user's PC: visual checks go to the manual checklist (Task 16).
- UI strings in French through `src/i18n/fr.json` and `src-tauri/src/messages.rs`; code and comments in English, matching the existing code.
- Settings stay `version: 1`; new fields through the leaf-by-leaf `repair`/`validate` in `settings/store.rs`: `capture.startMode: "region"` (`"region" | "window" | "last"`), `editor.recentColors: []` (0 to 8 `#RRGGBB`); `history.retentionDays` 7, 30, 90 or `null` (default 30).
- Every new Tauri command is listed in `src-tauri/build.rs` and allowed in the right `src-tauri/capabilities/*.json`; `src/lib/bindings.ts` is regenerated by `cargo test` and committed.
- A setting is shown only if it works: language, updates and tray timer stay hidden.
- History deletion never deletes a file saved in the user's folder.
- Values pinned by the spec: thumbnails 320 px wide JPEG; retention sweep at start then every 24 h; recent colours 8; spacing title → card 16 px, rows 16 px vertical / 20 px horizontal padding; refused file names: empty, `\ / : * ? " < > |`, Windows reserved names, existing file.
- Python file writes use `newline=''`. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` green after every task.

## Review Focus

1. **Never a duplicate, never a lost edit.** Save, undo back to the saved state (button greys), redo (button active), save again: one file, replaced; « nouvelle version » after that makes exactly one `(2)`. Test: Task 7 `saveState` cases and Rust `save_target`.
2. **History survives everything.** A J2 user with a `captures\` folder, a corrupt `index.json`, a capture deleted from the user's folder, an app killed during an index write: the history still opens and lists what exists. Tests: Task 4 `rebuild`, atomic write; Task 5 migration.
3. **Shortcuts the user can break.** Setting a combination Windows refuses, the same combination on two actions, or « Aucun » on every action must leave a working state and a clear message; the old shortcut stays active on refusal. Tests: Task 13 `validate_binding` and the duplicate case.
4. **Rename edge cases.** Rename to the current name, to a name differing only by case, while the file is open elsewhere (locked): no data loss, clear message. Tests: Task 9 `validate_stem` and `rename_plan`.
5. **Launch paths.** Installer « Lancer » (no args), Windows logon (`--autostart`), second instance, and autostart toggled off then on: the window opens exactly when the user launched it. Tests: Task 1 `launched_by_user`.
